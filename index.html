One workspace

Your entire API workflow. One workspace.

Requests, collections, environments, scripts, mocks and load tests in one application, with your workspace kept as plain files on your computer. All screenshots show the application with a fictional banking API and sample data.

  • Collections and foldersPlain files in a folder you choose, ready to review and diff in Git

Environments

Switch environments with confidence.

Keep development, test and production values separate, and switch with Ctrl E. When a production environment is active, the title and status bars turn red, Send reads Send to PROD, and sending requires confirmation by default.

Mock Server Beta

Mock an API before it exists.

  • Matches requests by method and exact path; each mock returns a status, headers and a JSON, XML or text body.
  • Runs inside LynxQ, on 127.0.0.1 by default, and never starts automatically.
  • Point an environment at it, or save any response as a mock.
  • Inject delays, failures and dropped connections to test client resilience.

Performance Lab Beta

From API requests to performance insights.

Run any saved request as a load test with virtual users, duration, ramp-up and an optional rate limit. Before it starts, LynxQ shows every target host and the maximum number of requests; afterwards it reports throughput, P50, P95 and P99 latency, and errors.

Results from a single run against a local mock server. Illustrative only, not a benchmark.

On the command line

The same engine, in your pipeline.

App lynxq-api.exe · Command line lynxq.exe

  • Runs collections from a workspace read-only, without a window or an account.
  • Secrets come from environment variables or the app's encrypted vault; values typed on the command line are refused.
  • Credentials are sent only to origins approved with --allow-origin; PROD environments require --allow-prod.
  • Writes JUnit and JSON reports, with exit codes for CI.
PowerShell · demo-bank
PS> lynxq run Accounts -e DEV --secret accessToken=env:DEMO_BANK_TOKEN
lynxq: Origin approval required: http://127.0.0.1:4000. Accounts/List accounts would send credentials there. Nothing was sent. If you trust it, pass --allow-origin http://127.0.0.1:4000.

2

Real runs of lynxq 0.1.0-alpha.1 in PowerShell, in the demo bank workspace, against LynxQ's Mock Server on this computer. First, without --allow-origin: refused before anything is sent, exit code 2. Privacy and security

Only the requests you send.

  • No telemetry, no account. LynxQ makes no network calls of its own, only the requests you send and the token requests they require.
  • Credential destination control. A destination from a workspace, an import or a clone is never trusted automatically: LynxQ asks before sending credentials to it.
  • Secrets stay out of your files. They are sealed in an encrypted vault (AES-256-GCM) on your computer, never in workspace files or History. Only the vault key is kept in Windows Credential Manager.
  • Explicit script approval. Scripts are off in every workspace until you enable them, and new or imported scripts wait for review.
