Check rows

On this page
  1. Columns
  2. Sources
  3. Operators
  4. Expected values
  5. Comparison rules
  6. Results and messages
  7. Examples

A Check row reads one value from the response and compares it. Add one with + Add check on the After response tab.

Columns

Section titled “Columns”
Column Meaning
On Switched-off rows do not run
Source What to read (see below)
Path The header or cookie name, the JSON or XML path, or the regex. Not used for Status, Status text, Time, Size and Text.
Compare The operator
Expected The value to compare with. Not used for exists, does not exist, is empty and is not empty. {{variables}} are resolved.

Sources

Section titled “Sources”
Source Path column Reads
Status — The status code, as a number
Status text — The reason phrase (empty for HTTP/2)
Time — Total time in milliseconds, to 0.1 ms
Size — Body size in bytes, as received
Header Header name The first header of that name (any case)
Cookie Cookie name That cookie's value from this response's Set-Cookie headers
JSON body JSON path, for example $.data.items[0].id The value at the path
XML body XPath, for example //m:AddResult The element's text or the attribute
Regex A regex, for example order-(\d+) The first capture group, or the complete match without groups
Text — The whole body as text

A JSON path may start without $: data.id reads as $.data.id. See the Paths reference.

Operators

Section titled “Operators”
Operator Expected Passes when
equals A value The value equals the expected value (see Comparison rules)
does not equal A value It does not
less than A number The value is a number below it
at most A number ≤
greater than A number >
at least A number ≥
contains Text The value's text contains it
does not contain Text It does not
matches regex A regex The regex matches anywhere in the value's text
exists — The value is in the response
does not exist — It is not
is empty — null, an empty string, array or object
is not empty — Anything else
length equals An integer The length of an array, object (number of keys) or text (in characters) equals it
length greater than An integer The length is greater
length less than An integer The length is smaller
is type number, text, true/false, array, object or null The value has that type. string, boolean and bool are accepted too.
is one of Values separated by commas The value equals any of them

Expected values

Section titled “Expected values”
  • Numbers (200, 0.5, -3), true, false and null are read as such.
  • Anything else is text. Quotes ("200" or 'ok') make a value text and are removed.
  • Time takes a unit: 500 ms, 0.5 s. Size takes B, KB or MB (1 KB = 1,024 bytes). Without a unit, Time is in milliseconds and Size in bytes.

Comparison rules

Section titled “Comparison rules”
  • Numbers compare exactly as decimals: 0.1 + 0.2 style rounding never makes a check fail. A text value that looks like a number ("12") compares as a number.
  • true / false / null compare with JSON booleans and null. Otherwise their text is compared.
  • Text compares exactly, including case.
  • contains works on the value's text. For a JSON object or array, that is its JSON text.

Results and messages

Section titled “Results and messages”

Each row gives one result, named like the row (status equals 200, or the line as written, see Line syntax), with a message on failure:

Situation Status Message
Value compared passed / failed got 404 (long values cut at 80 characters)
Source missing failed (passed for does not exist) not found in the response / not there
Not a number for a numeric operator failed got abc, which can't be compared as a number
No length (a number, say) failed got 5, which has no length
Expected value missing failed Fill in the expected value.
Path missing failed Fill in the JSON path.
Invalid regular expression failed The regex can't be read: …
JSON body over 16 MB not evaluated The body is too large for JSON paths

Not evaluated is never counted as passed.
