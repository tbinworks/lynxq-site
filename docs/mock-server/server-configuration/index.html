Server configuration, starting and network security

Starting and stopping

Section titled “Starting and stopping”
  • Start: the server section's Start server, the status-bar chip, or Mock: Start server.
  • Stop: the same places, or Mock: Stop server. Requests in flight and delayed requests get up to 2 seconds, then they are closed.
  • The server never starts by itself: not when the view opens, not when LynxQ API starts.
  • It counts as running only once the port is bound.
  • It keeps running while you use other views, and closing the Mock Server workspace does not stop it. It stops when LynxQ API closes.

Host

Section titled “Host”
Choice Listens on Notes
this computer only (default) 127.0.0.1 Only programs on this computer can reach it
all network interfaces 0.0.0.0 Warning: Other devices on your network can reach this server.

Clients on this computer call 127.0.0.1 either way.

Port

Section titled “Port”
  • 4000 by default, from 1 to 65535. Ports below 1024 are flagged as often reserved.
  • Host and port can only be changed while the server is stopped (Stop to change).
  • If the port is in use, the error says so and offers the next free port (Use port N), which starts the server there. The MOCK environment follows.

CORS

Section titled “CORS”

Allow CORS is off by default. When it is on:

  • a page served from this computer (http(s)://localhost:*, http(s)://127.0.0.1:*) may read the responses. They carry that page's own origin (Access-Control-Allow-Origin: <origin> with Vary: Origin, never *) and Access-Control-Expose-Headers: *;
  • a preflight (OPTIONS with Access-Control-Request-Method) is answered 204 with the allowed methods and the headers asked for, unless an OPTIONS mock answers that path;
  • any other website gets none of this;
  • a mock's own CORS headers win;
  • a note shows while it is on.

Protections

Section titled “Protections”
Protection Rule
Host check A request whose Host is not localhost, 127.0.0.1 or [::1] is refused with 421 and logged Refused: another host. A web page cannot reach your mocks by pointing its own domain name at this computer. On all interfaces, IP addresses are answered too, never a domain name.
Unmatched requests 404 with {"error":"no mock for GET /x"}, logged as unmatched. Never forwarded anywhere.
Request body Read up to 1 MB. More gets 413.
Connections 512 immediately; more wait to be accepted
Header timeout A client has 30 s to send its request headers
Activity Secret header and query values are hidden before they are recorded. Bodies are never kept.

The MOCK environment

Section titled “The MOCK environment”

The first mock you make creates an environment named MOCK (purple in the title bar) with baseUrl=http://127.0.0.1:<port>, kept in step with the port. Your other variables in it stay as you set them. Requests written as {{baseUrl}}/orders/42 reach the mock when it is active (Mock: Switch to MOCK environment).

Send to mock

Section titled “Send to mock”

Full URLs (https://api.example.com/orders/42) are not changed by an environment. Send to mock, under the Send button's arrow, sends one to the running mock once: the scheme, host and port are replaced, the path and query are kept, and the request itself is unchanged. If no mock answers that method and path, or the server is not running, it says so and sends nothing.

A response from the mock server is labelled Served by mock.
