lq is the only global LynxQ API adds to a script. It is a frozen object with no prototype: you cannot add to it, replace its members or reach them through Object.prototype. This page documents API version 1, the only version in LynxQ API v0.1.0.

Availability by phase

Section titled “Availability by phase”

Using a member in the wrong phase throws a PhaseError that names the right tab:

Member Before request After response
lq.version ✓ ✓
lq.env, lq.vars ✓ ✓
lq.uuid, lq.now, lq.base64, lq.sha256, lq.hmac ✓ ✓
lq.log ✓ ✓
lq.request ✓ read and change PhaseError
lq.skip ✓ PhaseError
lq.response PhaseError ✓ read only
lq.test, lq.expect PhaseError ✓

Conventions

Section titled “Conventions”
  • Optional options objects: unknown keys are ignored. Only own properties count.
  • Strict lookups: {strict: true} makes a missing value throw a ReferenceError instead of returning undefined.
  • Text: all text is UTF-8. Values passed where text is expected are converted with String(…) unless stated otherwise.
  • Masking: every secret value (3 characters or more), and its base64 and percent-encoded forms, is replaced with •••• in everything that leaves the script.

lq.version

Section titled “lq.version”

The API version this script runs with: 1. Read-only.

lq.env

Section titled “lq.env”

The active environment's variables, as this request sees them. Reads include values the request inherits from its folders and collection (environment values win). Writes go to the active environment.

lq.env.get

Section titled “lq.env.get”
Parameter Type Description
name string The variable's name, without braces
options.strict boolean Throw if missing. Default false.

Returns the value as text, or undefined when there is no such variable or it is switched off. Secret variables are readable.

Errors (strict only): ReferenceError: lq.env.get: no variable "tokn" plus where it looked.

lq.env.has

Section titled “lq.env.has”

true if the variable exists and is enabled.

lq.env.set

Section titled “lq.env.set”
Parameter Type Description
name string Not empty, no spaces or braces
value string, number or boolean Numbers and booleans are stored as text
options.secret boolean true: store the value in the vault and mask it. Omitted: a secret variable stays secret. false on a secret variable is refused.

Side effects: the change is visible immediately to the rest of this run and to later levels. It is written to the environment when the chain ends without an error (see all or nothing).

Errors:

  • lq.env.set: no environment is active. Pick one in the environment menu, or use lq.vars to keep the value for this run only.
  • lq.env.set: the variable name must not be empty / …must not contain spaces or braces
  • lq.env.set: "token" is a secret variable; a script can't make it public. Change it in the environment editor.
  • TypeError: lq.env.set: the value is undefined; use lq.env.unset to remove a variable (also for null)
  • TypeError: lq.env.set: the value must be text, a number or true/false, not an object. Use JSON.stringify on purpose. (also for arrays)

lq.env.unset

Section titled “lq.env.unset”

Removes the variable from the active environment (on success of the chain).

Errors: lq.env.unset: no environment is active. Pick one in the environment menu.

lq.vars

Section titled “lq.vars”

Run variables: same functions as lq.env, without an environment. A run variable lives for one Send, one Run all (shared by every request in it), or one Performance Lab virtual user. It is never persisted to a file or the vault.

{{name}} in a request is filled from run variables first, then the environment, then folders and collection. {secret: true} masks the value like an environment secret. Errors are as for lq.env, without the "no environment" case.

lq.uuid

Section titled “lq.uuid”

A random version 4 UUID, lower case, as {{$uuid}} gives.

lq.now

Section titled “lq.now”

The current time, from the host clock. There is no Date in scripts.

Field Meaning Example
ms Milliseconds since 1970-01-01 UTC 1763540003120
unix Whole seconds (as {{$timestamp}}) 1763540003
iso ISO 8601 UTC with milliseconds (as {{$isoTimestamp}}) 2026-11-19T08:13:23.120Z

The returned object is frozen. Each call reads the clock again.

lq.base64

Section titled “lq.base64”
  • encode encodes the UTF-8 bytes of text. {url: true} uses the URL-safe alphabet without padding (JWT segments).
  • decode accepts input with or without padding and returns UTF-8 text.

Errors:

  • lq.base64.decode: not valid base64 at character 17
  • lq.base64.decode: the decoded bytes aren't UTF-8 text. Version 1 scripts work with text only.

lq.sha256

Section titled “lq.sha256”

SHA-256 of the UTF-8 bytes of text. Lower-case hex by default.

Errors: lq.sha256: output must be "hex", "base64" or "base64url", not "binary"

lq.hmac

Section titled “lq.hmac”
Parameter Description
algorithm "sha1", "sha256" or "sha512"
key Text (used as UTF-8 bytes), or {base64: "…"} / {hex: "…"} for a binary key
message Text (UTF-8 bytes)
options.output "hex" (default), "base64" or "base64url"

Errors:

  • lq.hmac: the algorithm must be "sha1", "sha256" or "sha512", not "md5"
  • lq.hmac: the key is empty. Is the variable set? (an empty, undefined or null key: usually a secret with no value on this computer)
  • lq.hmac: the key isn't valid base64 / …isn't valid hex
  • TypeError: lq.hmac: the key must be text, {base64: …} or {hex: …}
  • an invalid output, as for lq.sha256

lq.log

Section titled “lq.log”

Writes one line to the Console of the Script window and of the response. Text is shown as is. Other values are shown as compact JSON, undefined as undefined, functions as [function], and BigInt as 123n. Values are separated by spaces.

  • Secret values are replaced with ••••.
  • Limits per run: 1,000 lines and 64 KB, and 1 KB per line. Past a limit, lines are counted, not kept: … 3,412 more lines not shown (limit 1,000 lines).
  • Logging never fails a script.

lq.request (Before request)

Section titled “lq.request (Before request)”

The request as it will be sent, before built-in auth is added. It is a copy: changes affect this send only, never the saved request. Every field is as written, with {{placeholders}}. Variables are resolved after the entire Before request execution chain, so a Before script can set a variable the request then uses.

lq.request.url

Section titled “lq.request.url”

The URL as written. Assigning changes it for this send.

Errors: lq.request.url: a URL can't contain a line break. Changing the scheme, host or port is refused at the end of the chain unless the level allows it (see Changing the host): Not sent: lq.request.url: a script can't send this request to another host (api.example.com → collect.example.net). To allow it, turn on "Scripts may change the host" in the Script window's options for collection Shop.

lq.request.resolvedUrl

Section titled “lq.request.resolvedUrl”

The URL with variables resolved now, including this run's changes so far.

lq.request.method

Section titled “lq.request.method”

One of GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS.

Errors: lq.request.method: "FETCH" isn't an HTTP method LynxQ sends

lq.request.headers

Section titled “lq.request.headers”
  • Includes the request-level headers and the inherited ones that are enabled. Built-in authentication is not there.
  • Names match in any case. set replaces every header of that name.
  • {resolved: true} gives the value with placeholders resolved now.

Errors: lq.request.headers.set: a header name can't contain ":" or spaces; lq.request.headers.set: "Host" is set by LynxQ; change lq.request.url instead (also Content-Length and Transfer-Encoding); TypeError: …: the value must be text, a number or true/false, not null; strict get: ReferenceError: lq.request.headers.get: no header "X-Trace".

lq.request.query

Section titled “lq.request.query”

The same as headers, for query parameters.

lq.request.body

Section titled “lq.request.body”
Function Behaviour
text() The body text for json, xml, text and graphql (the query text), and form as encoded a=1&b=2. Multipart and binary bodies cannot be read.
json() JSON.parse of text(). {strict: true} returns a read-only view that throws on a missing field.
set(text) Replaces the text and keeps the kind. Refused for form, multipart and binary bodies.
setJson(value) Stores JSON.stringify(value) and makes the kind json.

Errors: lq.request.body.text: a multipart body can't be read by a script in version 1; lq.request.body.set: a form body can't be set by a script in version 1, so its fields keep their table. Use setJson or a text body instead.; lq.request.body.json: the body isn't JSON (…); TypeError: lq.request.body.setJson: undefined can't be written as JSON.

lq.skip (Before request)

Section titled “lq.skip (Before request)”

Stops the Before request execution chain and does not send the request.

  • Nothing after it runs: not the rest of this script, not later levels, not the After response execution chain.
  • The Results show Skipped: <reason>. A Send shows Not sent: skipped by the request's Before script: . In Run all the step is skipped.
  • The skip stands even if the script catches the exception: the host records it first.
  • A skip keeps nothing: no lq.env or lq.vars change made before it, in this script or earlier levels.

Errors: TypeError: lq.skip: give a reason, so the result says why

lq.response (After response)

Section titled “lq.response (After response)”
  • statusText is empty when the server sent none (as HTTP/2 does).
  • headers.get matches names in any case. Several headers of one name are joined with ", ".
  • text() decodes the body with the Content-Type charset (UTF-8 by default). Bytes that cannot be decoded become U+FFFD.
  • json() parses the body. Both are computed on first use and cached for the run.
  • json({strict: true}) returns a read-only view that throws on a missing field: ReferenceError: lq.response.json: no field 'mising' at $.user.
  • Everything is read-only.

Errors:

  • lq.response.json: the body isn't JSON (…). Content-Type is text/html.
  • A body over 16 MB: text() and json() throw a NotEvaluatedError. The result is not evaluated, not failed.
  • Strict headers.get: ReferenceError: lq.response.headers.get: no header "X-Trace"

lq.test (After response)

Section titled “lq.test (After response)”

Runs fn immediately. If it returns, the test passes. If it throws (a failed expectation or any error), the test fails with that message, and the script goes on with the next statement.

  • Each test is one result, with source Script test.
  • At most 1,000 tests per run: lq.test: more than 1,000 tests in one run.
  • The time limit cannot be caught: it stops the whole run, and finished tests keep their results.

Errors: TypeError: lq.test: give the test a name; TypeError: lq.test: the second argument must be a function.

lq.expect (After response)

Section titled “lq.expect (After response)”

Every matcher returns undefined or throws an ExpectationError:

Matcher Passes when
toBe(expected) Object.is(received, expected)
toEqual(expected) Deep equality of JSON-like values: object keys in any order, arrays in order, undefined fields count as missing
toContain(item) received is a string containing item, or an array with an element toEqual to item
toMatch(pattern) received is a string and the RegExp (or pattern text, compiled with the u flag) matches
toBeGreaterThan(n) Both are numbers and received > n
toBeLessThan(n) Both are numbers and received < n
toHaveLength(n) received.length === n for a string or array
toBeDefined() received !== undefined
toBeNull() received === null
.not.<matcher> The matcher would fail. The message says expect(received).not.toBe(expected).
  • A matcher on the wrong type fails with a clear message rather than crashing, for example expect(received).toBeGreaterThan(expected): received must be a number, got text "12". Use Number(...) first.
  • An invalid pattern: toMatch: invalid regex: ….
  • Outside lq.test, a failed expectation is not swallowed: it stops the script, and the run is marked failed. It is never a silent pass.
