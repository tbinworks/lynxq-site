Opening the Export tab

Section titled “Opening the Export tab”
  • Collection: Export… in the palette: the whole workspace;
  • Export… in a collection's or folder's row menu: that item;
  • the Export tab of the Import | Export dialog.

What to export

Section titled “What to export”

The top of the tab says what is exported, in two lines: the item's name (or Whole workspace, or 3 items), then its counts, for example 1 folder · 3 requests. Details lists the items when there are several. Overlapping items (a folder and its parent) are exported once, the outer one winning.

Environments

Section titled “Environments”

Environments are chosen separately, in a short checklist with All / None and their DEV/TEST/PROD badges:

  • Ticked first: the environments that define a variable the exported items use and do not define themselves.
  • A warning, not a block: Uses {{token}}, which no selected environment defines.
  • The tab says how they are written, for example 2 environments, inside the LynxQ API file or 3 environments, as 3 files.

Formats

Section titled “Formats”
Format Writes Keeps
LynxQ API export One .json file Folders, inheritance and variables kept whole, for git or a teammate's Import. Collection and folder headers and variables, Builder rows and scripts are included.
Postman v2.1 A collection file per collection and an environment file per environment, in a folder you choose See Postman compatibility

Export as .zip… (under the Export button's arrow) is available for one collection or folder. The ZIP is its folder as it is in the workspace, without secrets.

Secret values

Section titled “Secret values”

Include secret values is off by default.

  • Off: Secret values go as names only: whoever imports the files is asked to set them. Secret variables, auth passwords, tokens and keys, and credential headers go as names only. A Postman secret variable keeps "type": "secret" with an empty value.
  • On: Passwords, tokens, keys and secret variables go into the files as they are: anyone with them can read them. Keep the files private.
  • OAuth2 client secrets are never exported.

See Secret handling during import and export.

Output

Section titled “Output”

The result lists every file written, the counts, and N things left out or changed with Show details. A name already in the target folder gets a number: nothing is overwritten.

Copying one request

Section titled “Copying one request”

To share one request, use Copy as cURL (secrets as placeholders) on its tab, row menu or History entry. See cURL.
